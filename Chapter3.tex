\chapter{Methodology}
\lhead{\emph{Chapter3}}

In this chapter, we outline the methodological framework used to develop and evaluate Graph Neural Network models for fraud detection on two benchmark datasets: the Amazon fraud dataset and the Yelp fraud dataset. We first describe both datasets and the preprocessing steps required to construct the multi-relational graphs, then discuss the three baseline architectures implemented---Relation-Aware GCN, Multi-Relation GraphSAGE, and CARE-GNN---and explain how each processes relational information. We then detail the reinforcement learning module used by CARE-GNN to adaptively filter neighbours, present our proposed extension, CAPN (Camouflage-Aware Policy Network), which replaces the heuristic RL module with a learned policy network, describe the LLM reasoning enrichment module that uses Claude to produce fraud-relevant risk scores for each node, and present the ablation study framework used to evaluate each component of CAPN systematically.

\section{Dataset Description}

The experiments in this study are conducted on two benchmark datasets for graph-based fraud detection: the Amazon fraud dataset and the Yelp fraud dataset (YelpChi). Both datasets model user behaviour through multi-relational graphs with anonymised numerical features.

\subsection{Amazon Fraud Dataset}

The Amazon dataset contains \textbf{11,944} users, each represented as a node with \textbf{25} numerical features describing behavioural and profile-based attributes (star rating distributions, review counts, and review statistics). Users are labelled as either benign~(0) or fraudulent~(1), with \textbf{11,123} benign users and \textbf{821} fraudulent users (\textbf{6.9\%} fraud rate). Nodes 0--3,304 are unlabelled; only nodes 3,305 and above carry labels. The dataset provides three relational graphs:

\begin{itemize}
    \item \textbf{UPU} (User--Product--User): connects users who reviewed the same products. The sparsest relation (avg.\ degree 30.4), providing the clearest fraud signal---fraudulent nodes have 32.5\% fraud neighbours vs.\ 13.2\% for benign nodes.
    \item \textbf{USU} (User--Seller--User): connects users who assigned the same star rating to the same seller within one week. Extremely dense (avg.\ degree 598.2) with weak homophily (13.0\% vs.\ 7.5\% fraud neighbours).
    \item \textbf{UVU} (User--View--User): connects users whose review texts have high TF-IDF cosine similarity. Moderately dense (avg.\ degree 174.6) with the strongest fraud signal---fraudulent nodes have 33.1\% fraud neighbours vs.\ only 1.5\% for benign nodes.
\end{itemize}

\section{Data Processing}
\vspace{1\baselineskip}

Data preprocessing plays a critical role in ensuring stable and high-performing Graph Neural Network models. Because the Amazon dataset carries a complex relational structure with heterogeneous edge types (UPU, USU, UVU), several transformations are applied both to the feature space and to the graph structure prior to training. The preprocessing serves three purposes: (i)~making node features comparable across dimensions, (ii)~normalising the graph for numerically stable aggregation, and (iii)~adapting the adjacency matrices to each GNN's aggregation mechanism.

\subsection{Feature Standardisation}
Standardisation prevents domination by high-magnitude features and stabilises gradient flow during message passing. The features were z-score normalised using training-set statistics only to avoid data leakage. Let \( X \in \mathbb{R}^{N \times D} \) denote the feature matrix, where \( N \) is the number of nodes and \( D \) is the number of features. For each feature dimension \( d \), the training mean \( \mu_d \) and standard deviation \( \sigma_d \) were computed, and normalisation was applied as:

\begin{equation}
X'_{id} = \frac{X_{id} - \mu_d}{\sigma_d + \epsilon}
\end{equation}

where \( \epsilon \) is a small constant to prevent division by zero. This ensures that all features have zero mean and unit variance, improving gradient flow during training.

\subsection{Graph Construction}
Three relational graphs are provided in the dataset:

\begin{itemize}
    \item \( \mathcal{G}_{\text{upu}} \): User--Product--User relation
    \item \( \mathcal{G}_{\text{usu}} \): User--Seller--User relation
    \item \( \mathcal{G}_{\text{uvu}} \): User--View--User relation
\end{itemize}

Each was stored as adjacency lists and converted to symmetric undirected adjacency matrices in compressed sparse row (CSR) format. Self-loops were explicitly removed to ensure meaningful neighbourhood aggregation.

\subsection{Graph Normalisation for GCN}
For the relation-aware GCN model, a top-\(p\) neighbour filtering strategy was applied to retain only the most informative neighbours for each node. Specifically, for each node \( i \), the top \( p = 10\% \) of neighbouring nodes were selected according to the cosine similarity of their feature vectors:

\begin{equation}
\text{sim}(i,j) = \frac{X_i \cdot X_j}{\|X_i\| \, \|X_j\|}
\end{equation}

After filtering, the graph was symmetrised and normalised using the standard GCN normalisation:

\begin{equation}
\hat{A} = D^{-\frac{1}{2}} (A + I) D^{-\frac{1}{2}}
\end{equation}

where \( A \) is the adjacency matrix, \( I \) is the identity matrix, and \( D \) is the diagonal degree matrix. This normalisation ensures scale-invariant message passing and stabilises training.

\subsection{Graph Normalisation for GraphSAGE}
For the multi-relation GraphSAGE model, row-normalisation was applied instead of top-\(p\) filtering:

\begin{equation}
\tilde{A} = D^{-1} A
\end{equation}

where each row is normalised by the corresponding node degree. This is consistent with the mean aggregator mechanism of GraphSAGE, in which each node computes the average of its neighbours' embeddings.

\subsection{CARE-GNN Internal Preprocessing}
Unlike GCN and GraphSAGE, CARE-GNN does not require external graph normalisation or neighbour filtering. Instead, it operates directly on the raw adjacency lists and performs dynamic, label-aware neighbour selection internally during each forward pass (described in Section~\ref{sec:care-gnn}). Features are passed to the model as z-score normalised tensors without additional graph-level preprocessing.

\subsection{Sparse Conversion}
All normalised adjacency matrices (for GCN and GraphSAGE) were converted from SciPy CSR format to PyTorch sparse tensors to enable efficient GPU computation:

\begin{equation}
A_{\text{sparse}} = \texttt{torch.sparse\_coo\_tensor}(i, v, \text{size} = A.\text{shape})
\end{equation}

where \( i \) stores the indices of non-zero entries and \( v \) stores their values.

\subsection{Train/Validation/Test Splits}
Stratified sampling was used to split the labelled nodes into 25\% training, 15\% validation, and 60\% test sets (random state = 2), maintaining label proportions across all splits. For Amazon, only nodes 3,305 and above are included in the split (nodes 0--3,304 are unlabelled). For Yelp, all 45,954 nodes participate in the split. The large test set (60\%) is standard for this benchmark and ensures robust evaluation on a representative sample.

\subsection{Class Imbalance Handling}
Two complementary strategies address class imbalance:

\begin{enumerate}
    \item \textbf{Under-sampling.} By default, CARE-GNN and CAPN employ 1:1 negative under-sampling: at each epoch, a random subset of benign nodes equal in size to the fraud nodes is sampled, producing balanced training batches.

    \item \textbf{Class weighting.} When under-sampling is disabled, inverse-frequency class weights are applied to the cross-entropy loss:
    \begin{equation}
    w_c = \frac{N}{2 \cdot n_c}
    \end{equation}
    where \( N \) is the total number of training samples and \( n_c \) is the count of class \( c \).
\end{enumerate}

\noindent
\textbf{Important:} class weighting and under-sampling are mutually exclusive. Applying class weights when under-sampling is already active creates a double-correction that causes the model to over-predict the minority class. In our implementation, class weights are only applied when under-sampling is disabled.

\section{Graph Neural Network Models}

This section describes the three GNN architectures used in this work: the Relation-Aware Graph Convolutional Network (GCN), Multi-Relation GraphSAGE, and CARE-GNN. All three models are designed to exploit the multiple relational graphs (UPU, USU, UVU) simultaneously and therefore capture different types of user interactions. While the models share the same input data and output format, they differ fundamentally in how they aggregate neighbourhood information, handle multi-relational structure, and---in the case of CARE-GNN---resist camouflage behaviour by fraudsters.

\subsection{Relation-Aware GCN}

The first model is based on the classical Graph Convolutional Network (GCN) framework \cite{kipf2017semi}, extended to handle multiple relation types. Each relation has its own linear transformation layer, and the outputs are fused through learnable softmax weights. Node features are first transformed separately for each relation, aggregated through the corresponding normalised adjacency matrices, and then combined via weighted fusion. The fused representation is passed through dropout and a non-linearity, followed by a classification layer with sigmoid activation.

For each node \( i \) and relation \( r \), the neighbourhood message is computed as:

\begin{equation}
H^{(1)}_r = \hat{A}_r X W_r
\end{equation}

where \( \hat{A}_r \) is the normalised adjacency matrix for relation \( r \), \( X \) is the input feature matrix, and \( W_r \) is the relation-specific weight matrix. All relation-specific outputs are fused through:

\begin{equation}
H^{(1)} = \sum_{r=1}^{R} \alpha_r H^{(1)}_r
\end{equation}

where \( \alpha_r \) are softmax-normalised learnable parameters:

\begin{equation}
\alpha_r = \frac{\exp(\theta_r)}{\sum_{k=1}^R \exp(\theta_k)}
\end{equation}

Finally, a linear classification layer is applied:

\begin{equation}
\hat{y} = \sigma \left( H^{(1)} W_{cls} \right)
\end{equation}

where \( W_{cls} \) is the classifier weight matrix and \( \sigma \) is the sigmoid activation function.

\subsection{Multi-Relation GraphSAGE}

The second model is based on the GraphSAGE framework \cite{hamilton2017inductive}, adapted to handle multiple relations. Unlike GCN, GraphSAGE performs inductive learning through explicit neighbourhood sampling and aggregation. In this work, full neighbourhood aggregation with mean pooling is used, and the model aggregates messages across relations by averaging them.

For each relation \( r \) and layer \( l \), the neighbourhood aggregation is defined as:

\begin{equation}
M^{(l)}_r = \hat{A}_r H^{(l)}
\end{equation}

where \( H^{(l)} \) represents the hidden node embeddings at layer \( l \) and \( \hat{A}_r \) is the row-normalised adjacency matrix for relation \( r \). The relation-specific messages are averaged:

\begin{equation}
M^{(l)} = \frac{1}{R} \sum_{r=1}^R M^{(l)}_r
\end{equation}

The node representations are then updated using a layer-wise linear transformation and non-linearity:

\begin{equation}
H^{(l+1)} = \sigma \left( W_{\text{self}}^{(l)} H^{(l)} + W_{\text{neigh}}^{(l)} M^{(l)} \right)
\end{equation}

where \( W_{\text{self}}^{(l)} \) and \( W_{\text{neigh}}^{(l)} \) are trainable weight matrices for self-node and neighbourhood messages respectively.

The final classification output is computed as:

\begin{equation}
\hat{y} = \sigma \left( H^{(L)} W_{cls} \right)
\end{equation}

where \( L = 2 \) is the number of GraphSAGE layers used in this work.

\subsection{CARE-GNN}
\label{sec:care-gnn}

The third and primary model is the CAmouflage-REsistant Graph Neural Network (CARE-GNN) \cite{dou2020enhancing}, specifically designed to address the camouflage problem in GNN-based fraud detection. Fraudsters employ two types of camouflage to evade detection: \textit{feature camouflage}, where they manipulate their attributes to resemble legitimate users, and \textit{relation camouflage}, where they deliberately establish connections with benign users to dilute suspiciousness signals during neighbourhood aggregation. Standard GNNs are vulnerable to both strategies, as they indiscriminately aggregate all neighbourhood information.

CARE-GNN addresses these challenges through three integrated modules: (i)~a label-aware similarity measure that quantifies the informativeness of each neighbour, (ii)~a reinforcement learning (RL) module that adaptively determines the optimal filtering threshold, and (iii)~a multi-relation aggregation mechanism that combines filtered neighbourhood information across relations.

\subsubsection{Label-Aware Similarity Measure}

To identify informative neighbours and resist feature camouflage, CARE-GNN employs a label-aware similarity measure based on a trainable node-label predictor. A single-layer MLP serves as the label predictor, mapping each node's input features to a two-class output:

\begin{equation}
S(v) = \text{MLP}(h_v) \in \mathbb{R}^2
\end{equation}

The similarity between a centre node \( v \) and a neighbour \( v' \) is then measured via the L1 distance on the first component of the predictor output:

\begin{equation}
D(v, v') = |S(v)[0] - S(v')[0]|
\end{equation}

Neighbours with smaller distances are considered more likely to share the same label as the centre node and are therefore more informative for aggregation. For each relation \( r \), the neighbours of node \( v \) are ranked by distance and the top-\( p_r \) fraction with the smallest distances are retained for aggregation, where \( p_r \) is the filtering threshold for relation \( r \).

\subsubsection{Intra-Relation Aggregation}

After neighbour filtering, intra-relation aggregation computes a neighbourhood embedding for each relation independently. For each relation \( r \), the filtered neighbours' features are mean-aggregated:

\begin{equation}
h^{(r)}_{\mathcal{N}(v)} = \text{ReLU}\left( \frac{1}{|\mathcal{N}_r(v)|} \sum_{u \in \mathcal{N}_r(v)} h_u \right)
\end{equation}

where \( \mathcal{N}_r(v) \) denotes the set of selected neighbours of node \( v \) under relation \( r \).

\subsubsection{Inter-Relation Aggregation}

The intra-relation embeddings from all relations are combined through an inter-relation aggregator. In this work, we primarily use the \textbf{GNN (Threshold)} variant, which uses the RL-learned filtering thresholds as inter-relation weights:

\begin{equation}
h_v = \text{ReLU}\left( W \cdot h_v + \sum_{r=1}^{R} p_r \cdot (W \cdot h^{(r)}_{\mathcal{N}(v)}) \right)
\end{equation}

where \( W \) is a shared transformation matrix and \( p_r \) is the filtering threshold for relation \( r \). This ties the inter-relation weighting directly to the RL-learned filtering quality: relations with higher thresholds (admitting more neighbours) receive proportionally higher weight in the final representation. Alternative inter-aggregation strategies (Attention, learnable Weight, and Mean) are evaluated in the ablation studies (Section~\ref{sec:ablation}).

\subsubsection{Training Objective}

The model is trained end-to-end with a combined loss function consisting of two components:

\begin{equation}
\mathcal{L} = \mathcal{L}_{\text{GNN}} + \lambda_1 \cdot \mathcal{L}_{\text{simi}}
\end{equation}

where \( \mathcal{L}_{\text{GNN}} \) is the cross-entropy loss on the final GNN predictions and \( \mathcal{L}_{\text{simi}} \) is the cross-entropy loss on the label predictor's output. The similarity loss ensures that the label predictor learns to distinguish fraudulent from benign nodes, which in turn produces meaningful distance scores for neighbour filtering. The hyperparameter \( \lambda_1 \) controls the relative importance of the similarity loss.

\section{Reinforcement Learning Module}
\label{sec:rl-module}

A key contribution of CARE-GNN is the use of reinforcement learning to adaptively determine the optimal neighbour filtering threshold \( p_r \) for each relation \( r \). Since the quality of the filtered neighbourhood cannot be assessed directly during training, the RL module formulates the threshold selection as a Bernoulli Multi-Armed Bandit (BMAB) problem.

\subsection{Problem Formulation}

The RL process is defined as a BMAB \( B(\mathcal{A}, f, T) \), where \( \mathcal{A} \) is the action space, \( f \) is the reward function, and \( T \) is the terminal condition. The RL agent (neighbour selector) interacts with the GNN by adjusting the filtering thresholds based on observed rewards.

\subsection{Action Space}

At each epoch, the RL agent selects one of two actions for each relation \( r \):

\begin{equation}
a_r = \begin{cases}
+\tau & \text{(increase threshold: keep more neighbours)} \\
-\tau & \text{(decrease threshold: keep fewer neighbours)}
\end{cases}
\end{equation}

where \( \tau = 0.02 \) is the step size. The threshold is updated as \( p_r \leftarrow p_r + a_r \) and clamped to \([0.001, 0.999]\) to prevent degenerate values.

\subsection{Reward Function}

The reward is based on the change in average neighbour distance between consecutive epochs. For each relation \( r \), the average distance across all neighbours of positive (fraudulent) nodes at epoch \( e \) is:

\begin{equation}
d_r(e) = \frac{1}{|\mathcal{V}^+|} \sum_{v \in \mathcal{V}^+} \frac{1}{|\mathcal{N}_r(v)|} \sum_{u \in \mathcal{N}_r(v)} D(v, u)
\end{equation}

where \( \mathcal{V}^+ \) denotes the set of positive centre nodes in the batch. The reward for relation \( r \) at epoch \( e \) is then defined as:

\begin{equation}
f(p_r, e) = \begin{cases}
+1 & \text{if } d_r(e-1) - d_r(e) \geq 0 \\
-1 & \text{otherwise}
\end{cases}
\end{equation}

A positive reward indicates that the average neighbour distance has decreased (neighbours became more similar), prompting the agent to increase the threshold and admit more neighbours. A negative reward indicates increasing distances, prompting the agent to tighten the filter.

\subsection{Threshold Dynamics}

The reward-action mapping produces the following training dynamics: as the label predictor improves during training, it learns to separate fraudulent from benign nodes more effectively. This causes the L1 distances between fraudulent centre nodes and their benign (camouflaged) neighbours to increase, generating predominantly negative rewards. Consequently, the filtering thresholds decrease from the initial value of 0.5, progressively excluding the most dissimilar---and likely camouflaged---neighbours. As the thresholds stabilise, the GNN aggregates information from an increasingly refined neighbourhood, improving classification performance.

\section{CAPN: Camouflage-Aware Policy Network}
\label{sec:capn}

While CARE-GNN's reinforcement learning module represents a significant advance over static neighbour selection, it exhibits several limitations that constrain its effectiveness against sophisticated camouflage strategies. This section presents the \textbf{Camouflage-Aware Policy Network (CAPN)}, the primary contribution of this thesis, which replaces the heuristic RL module with a learned policy network that addresses each of these limitations systematically.

\subsection{Limitations of the Original RL Module}

The original RL module (Section~\ref{sec:rl-module}) has four key limitations:

\begin{enumerate}
    \item \textbf{Global thresholds.} A single threshold \( p_r \) is shared across all nodes within each relation, ignoring the fact that different nodes may require different levels of filtering based on their local neighbourhood structure.
    \item \textbf{Binary rewards.} The reward signal is limited to \( \{+1, -1\} \), discarding information about the magnitude of improvement or degradation in neighbour quality.
    \item \textbf{Epoch-level updates.} Thresholds are adjusted once per epoch via a fixed step size \( \tau \), resulting in slow adaptation that cannot respond to batch-level variation.
    \item \textbf{Linear label predictor.} The label-aware similarity measure relies on a single linear layer \( \texttt{nn.Linear}(D, 2) \), which cannot capture non-linear feature-label relationships.
\end{enumerate}

CAPN addresses all four limitations through five integrated components: an enhanced label predictor, a state constructor, a policy network, a shaped reward function, and a multi-view distance metric.

\subsection{Enhanced Label Predictor}

CAPN replaces the original linear label predictor with a two-layer MLP that captures non-linear feature-label relationships:

\begin{equation}
S(v) = W_2 \cdot \text{ReLU}(W_1 \cdot x_v + b_1) + b_2
\end{equation}

\noindent
where \( W_1 \in \mathbb{R}^{d_h \times D} \), \( W_2 \in \mathbb{R}^{2 \times d_h} \), and \( d_h = \max(D/2, 32) \). Dropout with rate 0.3 is applied between the two layers. The enhanced predictor also computes a prediction confidence score based on the normalised entropy of the softmax output:

\begin{equation}
\text{conf}(v) = 1 - \frac{H(\text{softmax}(S(v)))}{\log C}
\end{equation}

\noindent
where \( H(\cdot) \) denotes Shannon entropy and \( C = 2 \) is the number of classes. A confidence of 1 indicates a deterministic prediction, while 0 indicates maximum uncertainty. This confidence is used as a component of the state vector for the policy network.

\subsection{State Constructor}

For the policy network to make informed per-node filtering decisions, it requires a comprehensive representation of each node's local context. The state constructor builds a state vector for each node \( v \) in each relation \( r \) by concatenating the node's features with five structural and label-aware statistics:

\begin{equation}
\mathbf{s}_v^r = \left[ x_v, \; \text{conf}(v), \; \hat{d}_r(v), \; \bar{\delta}_r(v), \; J_r(v), \; \sigma_r(v) \right]
\end{equation}

\noindent
yielding a state dimension of \( D + 5 \). Each component is defined as follows:

\begin{itemize}
    \item \textbf{Node features} \( x_v \in \mathbb{R}^D \): the raw feature vector of node \( v \).

    \item \textbf{Label confidence} \( \text{conf}(v) \in [0, 1] \): the normalised entropy-based confidence from the enhanced label predictor (Equation above).

    \item \textbf{Normalised degree} \( \hat{d}_r(v) \): the degree of node \( v \) in relation \( r \), normalised by the maximum degree in that relation:
    \begin{equation}
    \hat{d}_r(v) = \frac{|\mathcal{N}_r(v)|}{\max_{u \in \mathcal{V}} |\mathcal{N}_r(u)|}
    \end{equation}

    \item \textbf{Mean label distance} \( \bar{\delta}_r(v) \): the average L1 distance between the label predictor scores of \( v \) and its neighbours in relation \( r \):
    \begin{equation}
    \bar{\delta}_r(v) = \frac{1}{|\mathcal{N}_r(v)|} \sum_{u \in \mathcal{N}_r(v)} |S(v)_0 - S(u)_0|
    \end{equation}

    \item \textbf{Structural overlap} \( J_r(v) \): the Jaccard similarity between the neighbours of \( v \) in relation \( r \) and in the homogeneous graph:
    \begin{equation}
    J_r(v) = \frac{|\mathcal{N}_r(v) \cap \mathcal{N}_{\text{homo}}(v)|}{|\mathcal{N}_r(v) \cup \mathcal{N}_{\text{homo}}(v)|}
    \end{equation}

    \item \textbf{Feature variance} \( \sigma_r(v) \): the mean feature-wise variance across the neighbours of \( v \) in relation \( r \):
    \begin{equation}
    \sigma_r(v) = \frac{1}{D} \sum_{d=1}^{D} \text{Var}\left( \{ x_{u,d} : u \in \mathcal{N}_r(v) \} \right)
    \end{equation}
    This is computed only when \( |\mathcal{N}_r(v)| \geq 2 \); otherwise it defaults to zero.
\end{itemize}

\noindent
The state vector provides the policy network with sufficient information to assess each node's neighbourhood quality: nodes with high mean distance, low structural overlap, or high feature variance among neighbours are likely surrounded by camouflaged connections and may benefit from more aggressive filtering.

\subsection{Policy Network}
\label{sec:policy-network}

The policy network is a neural network that maps state vectors to per-node filtering thresholds via a Beta distribution. It consists of a shared feature extractor followed by per-relation output heads.

\subsubsection{Architecture}

The shared feature extractor is a two-layer MLP:

\begin{equation}
\mathbf{h} = \text{ReLU}\left( W_4 \cdot \text{ReLU}\left( W_3 \cdot \mathbf{s}_v^r + b_3 \right) + b_4 \right)
\end{equation}

\noindent
where \( W_3 \in \mathbb{R}^{64 \times (D+5)} \) and \( W_4 \in \mathbb{R}^{32 \times 64} \). This shared representation is then passed to one of \( R \) relation-specific linear heads:

\begin{equation}
\mathbf{o}_r = W_r^{\text{head}} \cdot \mathbf{h} + b_r^{\text{head}}, \qquad W_r^{\text{head}} \in \mathbb{R}^{2 \times 32}
\end{equation}

\noindent
Each head outputs two values that parameterise a Beta distribution.

\subsubsection{Beta Distribution Parameterisation}

The two outputs are transformed via the softplus function with a positive offset to produce valid Beta distribution parameters:

\begin{equation}
\alpha_v^r = \text{softplus}(\mathbf{o}_{r,0}) + 0.5, \qquad \beta_v^r = \text{softplus}(\mathbf{o}_{r,1}) + 0.5
\end{equation}

\noindent
The offset of 0.5 ensures that both parameters remain bounded away from zero, preventing degenerate distributions. The filtering threshold for node \( v \) in relation \( r \) is then obtained as:

\begin{equation}
t_v^r \sim \text{Beta}(\alpha_v^r, \beta_v^r) \qquad \text{(training)}
\end{equation}

\begin{equation}
t_v^r = \frac{\alpha_v^r}{\alpha_v^r + \beta_v^r} \qquad \text{(inference)}
\end{equation}

\noindent
During training, thresholds are sampled stochastically from the Beta distribution to enable exploration; during inference, the deterministic mean is used. The number of neighbours retained for node \( v \) in relation \( r \) is:

\begin{equation}
k_v^r = \max\left(1, \; \left\lceil |\mathcal{N}_r(v)| \times t_v^r \right\rceil \right)
\end{equation}

\subsection{Multi-View Distance}

The original CARE-GNN uses only L1 label-aware distance to rank neighbours. CAPN extends this with a multi-view distance that combines label-aware and structural signals:

\begin{equation}
d(v, u, r) = \gamma_r \cdot |S(v) - S(u)|_1 + (1 - \gamma_r) \cdot \left(1 - \frac{|\mathcal{N}_r(v) \cap \mathcal{N}_r(u)|}{|\mathcal{N}_r(v) \cup \mathcal{N}_r(u)|}\right)
\end{equation}

\noindent
where \( \gamma_r \in [0, 1] \) is a per-relation mixing parameter (default \( \gamma_r = 0.7 \)) that controls the relative importance of label-aware versus structural distance. The structural component measures the Jaccard distance between the neighbourhoods of the centre node and its neighbour, capturing topological dissimilarity that is not visible through feature-based similarity alone. This is particularly effective against relation camouflage, where fraudsters establish connections with benign users but maintain structurally different neighbourhood patterns.

\subsection{Shaped Reward Function}

CAPN replaces the binary reward of the original RL module with a continuous, three-component shaped reward that provides richer training signal:

\begin{equation}
R = w_1 \cdot \text{clamp}\!\left(\frac{\bar{d}_{t-1} - \bar{d}_t}{|\bar{d}_{t-1}| + \epsilon}, \, -1, \, 1\right) + w_2 \cdot \left(\text{acc}_t - \hat{\text{acc}}_t\right) - w_3 \cdot \overline{|t - 0.5|}
\end{equation}

\noindent
where the three components are:

\begin{enumerate}
    \item \textbf{Distance improvement} (weight \( w_1 = 0.5 \)): measures the relative change in average neighbour distance between consecutive batches, normalised by the previous distance and clamped to \([-1, 1]\).

    \item \textbf{Accuracy signal} (weight \( w_2 = 0.3 \)): measures the difference between the current batch accuracy \( \text{acc}_t \) and an exponential moving average (EMA) baseline \( \hat{\text{acc}}_t \), with decay factor 0.95:
    \begin{equation}
    \hat{\text{acc}}_{t+1} = 0.95 \cdot \hat{\text{acc}}_t + 0.05 \cdot \text{acc}_t
    \end{equation}

    \item \textbf{Threshold regularisation} (weight \( w_3 = 0.2 \)): penalises extreme threshold values by computing the mean absolute deviation from 0.5 across all relations, preventing the policy from collapsing to trivially aggressive or permissive filtering.
\end{enumerate}

\noindent
The reward weights sum to 1.0 by design, ensuring a balanced trade-off between neighbour quality improvement, classification performance, and threshold stability.

\subsection{Training Objective}

CAPN is trained end-to-end with a three-term loss function that combines supervised learning with policy gradient optimisation:

\begin{equation}
\mathcal{L} = \mathcal{L}_{\text{GNN}} + \lambda_1 \cdot \mathcal{L}_{\text{label}} + \lambda_{\pi} \cdot \mathcal{L}_{\text{policy}}
\end{equation}

\noindent
where the first two terms are identical to CARE-GNN (Equation~20), and the policy gradient loss is computed via the REINFORCE estimator \cite{williams1992simple}:

\begin{equation}
\mathcal{L}_{\text{policy}} = -R \cdot \sum_{r=1}^{R} \frac{1}{|\mathcal{B}|} \sum_{v \in \mathcal{B}} \log \pi_\theta(t_v^r \mid \mathbf{s}_v^r)
\end{equation}

\noindent
where \( \pi_\theta \) is the policy network parameterised by \( \theta \), \( t_v^r \) is the sampled threshold, \( \mathbf{s}_v^r \) is the state vector, \( \mathcal{B} \) is the current mini-batch, and \( R \) is the shaped reward. The log-probability of the Beta distribution is computed analytically as:

\begin{equation}
\log \pi_\theta(t \mid \alpha, \beta) = (\alpha - 1) \log t + (\beta - 1) \log(1 - t) - \log B(\alpha, \beta)
\end{equation}

\noindent
where \( \log B(\alpha, \beta) = \log \Gamma(\alpha) + \log \Gamma(\beta) - \log \Gamma(\alpha + \beta) \).

A dual optimiser strategy is employed: the GNN parameters (embedding layers, aggregators, classifier) are trained with Adam at learning rate \( 1 \times 10^{-2} \), while the policy network parameters are trained with a separate Adam optimiser at learning rate \( 1 \times 10^{-3} \). Both optimisers are updated at every mini-batch, enabling the policy to adapt rapidly to evolving neighbourhood statistics during training.

\subsection{Implementation Details}

Several implementation details are critical for stable CAPN training:

\subsubsection{Separate Gradient Clipping}
REINFORCE gradients are inherently high-variance compared to supervised gradients. Joint gradient clipping at a single threshold (e.g., 1.0) crushes the policy gradients, preventing the policy from learning. We therefore apply \textbf{separate gradient clipping}: GNN parameters are clipped at max norm 1.0, while policy network parameters are clipped at max norm 5.0, allowing the policy sufficient gradient magnitude to learn from the noisy REINFORCE signal.

\subsubsection{SafeLgamma for CUDA Compatibility}
The Beta log-probability computation (Equation~38) requires evaluating \( \log \Gamma(\cdot) \) and its derivative \( \psi(\cdot) \) (digamma). On certain CUDA configurations, PyTorch's JIT compilation of these special functions fails with NVRTC errors. We implement a custom autograd function, \texttt{SafeLgamma}, that moves the lgamma/digamma operations to CPU and transfers results back to GPU, ensuring numerical correctness across all hardware configurations.

\subsubsection{NaN Protection}
Large policy loss weights or extreme Beta distribution parameters can occasionally produce NaN losses during early training. Two guards are applied: (i)~any NaN or Inf loss triggers a batch skip (the backward pass and optimiser step are not executed), and (ii)~prediction scores containing NaN values are replaced with 0.5 before metric computation to prevent evaluation crashes.

\subsubsection{Jaccard Distance Caching}
The structural Jaccard distance in the multi-view distance (Equation~34) requires set intersection and union operations for each node-neighbour pair. Since Jaccard distance is symmetric ($d(v,u) = d(u,v)$) and the graph structure is static, we cache computed distances in a dictionary keyed by $(\min(v,u), \max(v,u), r)$, reducing the computational cost of repeated evaluations.

\subsection{LLM Prior Warm-Starting}

To accelerate policy convergence, CAPN optionally incorporates pre-generated domain priors from a large language model (LLM). For each relation, two scores are provided: an \textit{importance} score reflecting the relation's informativeness for fraud detection, and a \textit{camouflage risk} score estimating the susceptibility of the relation to camouflage manipulation. These priors are used in two ways:

\begin{enumerate}
    \item \textbf{Policy network bias initialisation.} The per-relation head biases are set according to the camouflage risk:
    \begin{equation}
    b_{\alpha}^r = 1.0 - c_r, \qquad b_{\beta}^r = 1.0 + c_r
    \end{equation}
    where \( c_r \in [0, 1] \) is the camouflage risk for relation \( r \). Higher risk produces a lower initial \( \alpha/\beta \) ratio, biasing the policy towards more aggressive filtering for high-risk relations from the start of training.

    \item \textbf{Multi-view distance initialisation.} The per-relation mixing parameter \( \gamma_r \) is initialised from the importance score, allowing relations deemed more informative to place greater weight on label-aware distance.
\end{enumerate}

\section{LLM Reasoning Enrichment Module}
\label{sec:llm-reasoning}

A key contribution of this thesis is the integration of Large Language Model (LLM) reasoning into the CAPN state vector. Rather than using LLMs as generic text encoders---which we show to be ineffective (Study A6)---we use the Claude LLM as a \emph{reasoning engine} that analyses each node's structural profile and produces fraud-relevant risk assessments. This section describes the preprocessing pipeline, the reasoning score generation, and the integration into CAPN.

\subsection{Node Statistics Preprocessing}

As a one-time preprocessing step, we compute 26 structural statistics per node from the multi-relational graph. These statistics are organised into four categories:

\begin{enumerate}
    \item \textbf{Per-relation connectivity (12 features):} For each of the three relations, we compute the node degree, degree percentile rank (relative position within the degree distribution), label disagreement with training-set neighbours (fraction of neighbours with a different label), and mean feature variance across neighbours.

    \item \textbf{Cross-relation statistics (6 features):} Jaccard overlap between neighbour sets of each relation pair (e.g., UPU$\cap$USU / UPU$\cup$USU), and degree ratios between relation pairs. These capture whether a node's connectivity patterns are consistent or divergent across relations---a key camouflage indicator.

    \item \textbf{Feature anomaly (2 features):} The number of features with $|z| > 2$ (extreme features) and the mean absolute z-score, both computed using training-set statistics only to prevent data leakage.

    \item \textbf{Higher-order topology (6 features):} For each relation, the 2-hop neighbourhood size (number of unique nodes reachable in exactly two hops, excluding direct neighbours) and the ego-network density (fraction of possible edges among the node's neighbours that actually exist). High ego-density indicates clique-like structure potentially associated with coordinated fraud.
\end{enumerate}

\noindent
All statistics are precomputed and stored in a NumPy compressed archive. Label-dependent statistics use training labels only, ensuring no information leakage into validation or test sets.

\subsection{Claude Reasoning Scores}

For each node, its 26-dimensional structural profile is formatted as a structured text prompt and sent to the Claude LLM (Haiku model). The prompt presents the node's per-relation statistics, cross-relation overlap, and feature anomaly scores, and requests six fraud-relevant risk assessments returned as a JSON object:

\begin{enumerate}
    \item \textbf{Structural anomaly} $\in [0, 1]$: how unusual is the node's connectivity pattern compared to typical nodes.
    \item \textbf{Relation consistency} $\in [0, 1]$: how consistent is the node's behaviour across all three relations (low values indicate potential camouflage).
    \item \textbf{Neighbourhood risk} $\in [0, 1]$: how suspicious are the node's neighbours based on training-label statistics.
    \item \textbf{Feature anomaly} $\in [0, 1]$: how statistically unusual are the node's features.
    \item \textbf{Coordination signal} $\in [0, 1]$: likelihood that the node participates in coordinated or organised behaviour (e.g., fraud rings).
    \item \textbf{Isolation score} $\in [0, 1]$: structural isolation versus deep embeddedness in the graph.
\end{enumerate}

\noindent
The value of using an LLM here---rather than simple formulas---lies in its ability to reason about \emph{cross-feature interactions}. For example, a node with normal degree but extreme ego-density and high label disagreement in one relation suggests a tightly-connected fraud clique that has disguised its individual connectivity. Simple linear formulas treat each statistic independently; the LLM can recognise such combinatorial patterns.

Nodes are batched (5 per API call) to reduce request overhead, and results are checkpointed every 500 nodes for fault tolerance. A deterministic template-based fallback computes the same six scores via heuristic formulas when API access is unavailable. The scores are generated once and stored as a $[N, 6]$ tensor for reuse across all training runs.

\subsection{Integration into CAPN State Vector}

The enrichment features are integrated into the policy state vector via a learned 2-layer MLP projector:

\begin{equation}
\mathbf{e}_v = W_6 \cdot \text{ReLU}(W_5 \cdot \mathbf{f}_v + b_5) + b_6
\end{equation}

\noindent
where $\mathbf{f}_v$ is the enrichment feature vector (26 structural features, 6 reasoning scores, or the 32-dimensional concatenation of both, depending on enrichment mode) and the projector outputs a 16-dimensional vector. The enriched state vector becomes:

\begin{equation}
\mathbf{s}_v^r = \left[ x_v, \; \text{conf}(v), \; \hat{d}_r(v), \; \bar{\delta}_r(v), \; J_r(v), \; \sigma_r(v), \; \mathbf{e}_v \right]
\end{equation}

\noindent
yielding a state dimension of $D + 5 + 16 = D + 21$. The projector parameters are included in the policy optimiser's parameter group and trained end-to-end with the policy network. Three enrichment modes are supported:

\begin{itemize}
    \item \texttt{structural}: only the 26 graph statistics ($\mathbf{f}_v \in \mathbb{R}^{26}$).
    \item \texttt{reasoning}: only the 6 Claude reasoning scores ($\mathbf{f}_v \in \mathbb{R}^{6}$).
    \item \texttt{both}: concatenation of both ($\mathbf{f}_v \in \mathbb{R}^{32}$).
\end{itemize}


\section{Ablation Study Design}
\label{sec:ablation}

To systematically evaluate each component of CAPN, we design seven ablation studies that isolate individual design decisions while holding all other hyperparameters constant. All studies are evaluated on both the Amazon and Yelp datasets.

\subsection{Study A1: CAPN vs Original RL}

The central experiment compares the full CAPN system against CARE-GNN with its original heuristic RL module. This measures the aggregate effect of all CAPN components: the learned policy network, the MLP label predictor, multi-view distance, and shaped reward.

\subsection{Study A2: Label Predictor Isolation}

This study disentangles the contribution of the enhanced MLP label predictor from the policy network by comparing three configurations:
\begin{enumerate}
    \item \textbf{Linear predictor}: Original CARE-GNN with \texttt{nn.Linear(D, 2)} classifier.
    \item \textbf{MLP predictor (no policy)}: CARE-GNN with the two-layer MLP label predictor but the original heuristic RL. This isolates the classifier improvement.
    \item \textbf{MLP predictor + policy (CAPN)}: Full CAPN. The difference between this and configuration~2 measures the policy network's incremental contribution.
\end{enumerate}

\subsection{Study A3: Reward Shaping}

This study evaluates whether the three-component shaped reward improves over the original binary reward, and which component contributes most:
\begin{itemize}
    \item \textbf{Binary reward}: Original RL ($\pm 1$ based on distance change).
    \item \textbf{Shaped reward}: Full CAPN reward ($w_1 = 0.5, w_2 = 0.3, w_3 = 0.2$).
    \item \textbf{Distance only}: $w_1 = 1.0, w_2 = 0, w_3 = 0$. Tests filtering quality in isolation.
    \item \textbf{Accuracy only}: $w_1 = 0, w_2 = 1.0, w_3 = 0$. Tests task-level signal in isolation.
\end{itemize}

\subsection{Study A4: LLM Prior Initialisation}

Evaluates whether LLM-derived priors for policy network bias initialisation and multi-view distance mixing parameters accelerate convergence or improve final performance, comparing CAPN with and without priors.

\subsection{Study A5: Policy Loss Weight Sensitivity}

A sensitivity analysis over $\lambda_\pi \in \{0.01, 0.05, 0.1, 0.5\}$, testing the robustness of CAPN to the balance between supervised GNN loss and the REINFORCE policy gradient loss.

\subsection{Study A6: LLM Semantic State Enrichment (v1)}

Evaluates whether augmenting the policy state vector with projected sentence-transformer embeddings of node relational profiles improves threshold decisions. The base state has dimension $D + 5$; the enriched state adds 16 dimensions from a learned projector ($384 \to 64 \to 16$) applied to pre-computed sentence embeddings of each node's structural statistics.

\subsection{Study A7: LLM Reasoning State Enrichment (v2)}
\label{sec:enrichment-v2}

Motivated by the failure of the v1 sentence-transformer approach (Study A6), this study evaluates a redesigned enrichment pipeline that avoids the lossy text round-trip. Instead of converting numerical statistics to text and re-encoding them, we employ two complementary enrichment channels:

\begin{enumerate}
    \item \textbf{Direct graph structural features.} The precomputed node statistics---degrees, percentile ranks, label disagreement, neighbour feature variance, cross-relation Jaccard overlap, degree ratios, feature z-scores, 2-hop neighbourhood size, and ego-network density---are loaded as a 26-dimensional numeric vector per node and projected through a 2-layer MLP ($26 \to 52 \to 16$). This preserves numerical precision that the sentence-transformer destroyed.

    \item \textbf{Claude API reasoning scores.} For each node, its structural profile is sent to the Claude LLM (Haiku), which returns six fraud-relevant risk assessments:
    \begin{itemize}
        \item \textit{structural\_anomaly}: how unusual is this node's connectivity pattern (0 = typical, 1 = extreme outlier).
        \item \textit{relation\_consistency}: how consistent is behaviour across the three relations (0 = very inconsistent, 1 = uniform).
        \item \textit{neighbourhood\_risk}: how suspicious are the neighbours based on training-label statistics (0 = clean, 1 = mostly fraudulent).
        \item \textit{feature\_anomaly}: how statistically unusual are the node's features (0 = normal, 1 = extreme outlier).
        \item \textit{coordination\_signal}: likelihood of coordinated or organised behaviour (0 = independent, 1 = strong coordination).
        \item \textit{isolation\_score}: structural isolation versus embeddedness (0 = deeply embedded, 1 = peripheral).
    \end{itemize}
    Unlike the sentence-transformer approach, Claude is used to \emph{reason about pattern interactions}---for example, recognising that high ego-density combined with high label disagreement suggests a fraud ring, which a simple formula cannot capture. The six scores are produced once as a preprocessing step and stored as a $[N, 6]$ tensor.
\end{enumerate}

A template-based heuristic mode is also provided, where the six reasoning scores are computed via deterministic formulas rather than API calls, enabling cost-free experimentation. The study evaluates four configurations in a $2 \times 2$ ablation:
\begin{itemize}
    \item \textbf{CAPN (baseline)}: no enrichment ($\text{enrichment\_mode} = \text{none}$).
    \item \textbf{CAPN + structural}: structural features only ($\text{enrichment\_mode} = \text{structural}$).
    \item \textbf{CAPN + reasoning}: Claude reasoning scores only ($\text{enrichment\_mode} = \text{reasoning}$).
    \item \textbf{CAPN + both}: structural features and reasoning scores concatenated ($\text{enrichment\_mode} = \text{both}$).
\end{itemize}

\noindent
The v1 LLM semantic state enrichment shows minimal effect ($-0.19$pp AUC, $+0.06$pp AP). The pipeline computes node relational statistics (degrees, disagreement, overlap), converts them to natural language descriptions via templates, encodes them with a sentence-transformer (\texttt{all-MiniLM-L6-v2}), and projects the 384-dimensional embeddings down to 16 dimensions. Analysis reveals that this is a \textbf{lossy round-trip}: the sentence-transformer re-encodes numerical statistics already present in the base state through a text bottleneck, destroying numerical precision and adding no genuinely novel information. This motivates the redesigned v2 enrichment pipeline evaluated in Study A7.

\subsection{A7: LLM Reasoning State Enrichment (v2)}

Having diagnosed the v1 failure as a lossy numerical$\to$text$\to$embedding round-trip, we evaluate the redesigned enrichment pipeline (Section~\ref{sec:enrichment-v2}) that injects graph statistics directly as numeric features and uses LLM reasoning for pattern interaction analysis.

\begin{table}[ht]
\centering
\begin{tabular}{lcccccc}
\toprule
Configuration & GNN AUC & GNN AP & GNN F1 & Precision & Recall & Label F1 \\
\midrule
CAPN (baseline) & 0.9445 & 0.8568 & 0.8994 & 0.9074 & 0.8938 & 0.8935 \\
CAPN + structural & 0.9436 & 0.8546 & 0.8671 & 0.8497 & 0.8888 & 0.8891 \\
\textbf{CAPN + reasoning} & \textbf{0.9450} & \textbf{0.8595} & \textbf{0.9000} & \textbf{0.9084} & \textbf{0.8940} & \textbf{0.8945} \\
CAPN + both & 0.9431 & 0.8548 & 0.8744 & 0.8614 & 0.8906 & 0.8891 \\
\bottomrule
\end{tabular}
\caption{LLM reasoning state enrichment (v2) on Amazon. Results use template-mode heuristic scores. Bold indicates best per column.}
\label{tab:capn-enrichment}
\end{table}

\noindent
The v2 enrichment results reveal a clear pattern:

\begin{enumerate}
    \item \textbf{Reasoning scores improve all GNN metrics.} CAPN + reasoning achieves the highest AUC (+0.05pp), AP (+0.27pp), F1 (+0.06pp), and precision (+0.10pp) over the baseline. The six reasoning scores capture cross-feature interaction patterns (e.g., high ego-density combined with high label disagreement indicating a fraud ring) that are not visible in the individual base state statistics.

    \item \textbf{Structural features alone hurt F1 ($-$3.23pp).} Despite adding 26 genuinely new features (2-hop reach, ego-density, cross-relation degree ratios, feature z-scores), the projector MLP introduces noise that dilutes the existing state signal. The 26-dimensional input is relatively high compared to the base state's 5 structural statistics, and the projector ($26 \to 52 \to 16$) has many more parameters to overfit.

    \item \textbf{Combining both dilutes the reasoning signal.} When structural features and reasoning scores are concatenated ($32 \to 16$ projection), the noisy structural features dominate the small but informative reasoning scores, producing results closer to the structural-only configuration.

    \item \textbf{v2 reasoning outperforms v1 sentence-transformer.} Comparing CAPN + reasoning (AUC 0.9450) with v1 LLM state (AUC 0.9426), the reasoning-only approach gains +0.24pp AUC by avoiding the lossy text encoding and instead providing compact, fraud-relevant assessments.
\end{enumerate}

\noindent
These results demonstrate that \emph{how} LLM knowledge is integrated matters more than whether it is integrated. The sentence-transformer approach (v1) degraded information; the reasoning score approach (v2) adds genuinely novel pattern-level analysis. Claude API reasoning scores, which capture more nuanced pattern interactions than the template heuristics used here, are expected to improve these results further.

\noindent
Key findings from the Amazon evaluation:
\begin{enumerate}
    \item \textbf{CAPN improves over CARE-GNN} on the primary ranking metrics (+0.47pp AUC, +0.33pp AP), validating the learned policy approach.
    \item \textbf{The policy network is essential}, not just the MLP predictor. The MLP alone hurts GNN performance; the policy network recovers and surpasses the baseline.
    \item \textbf{LLM priors provide small but consistent gains}, with the best overall configuration being CAPN + LLM priors (AUC 0.9453).
    \item \textbf{CAPN is robust to hyperparameter choice}: the policy loss weight $\lambda_\pi$ can vary 50$\times$ with negligible impact.
    \item \textbf{LLM semantic state enrichment (v1) fails} due to the lossy sentence-transformer text bottleneck, producing neutral-to-negative results.
    \item \textbf{LLM reasoning state enrichment (v2) succeeds}: Claude reasoning scores add +0.05pp AUC and +0.27pp AP by providing compact fraud-relevant pattern analysis that avoids the text round-trip. This demonstrates that the \emph{form} of LLM integration---reasoning scores rather than text embeddings---is the critical design choice.
\end{enumerate}
