# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project context

This repo is a Master's thesis project: a unified **GNN + RL + LLM framework** for graph-based fraud
detection, built on top of CARE-GNN (Dou et al. 2020). The upstream README documents the original
CARE-GNN release; this thesis extends it with CAPN (Camouflage-Aware Policy Network) and an LLM
pillar. Thesis chapters live in `Chapter2 (1).tex`, `Chapter3.tex`, `Chapter4.tex`; the slide deck
in `Presentation.pptx` / `Presentation.tex`.

## Environment

- Use the conda env `torch_cuda`. From a bash shell on Windows the canonical interpreter path is
  `C:/Users/fadyh/miniconda3/envs/torch_cuda/python.exe`. `conda run -n torch_cuda` triggers a
  bug on multi-line `python -c` input — write a script file or call the `python.exe` directly.
- Dependencies are pinned in `requirements.txt`. LLM calls need the `anthropic` package and an
  `ANTHROPIC_API_KEY` env var; without a key the LLM pipelines fall back to deterministic
  template scoring and the failure rate is logged.
- Datasets must be unzipped first (`data/Amazon.zip`, `data/YelpChi.zip`); adjacency lists are
  regenerated by `data_process.py` and cached as `data/{amz,yelp}_*_adjlists.pickle`. Most code
  paths read the cached `.npy` / `.pickle` files, not the raw `.mat`.

## Common commands

```bash
# Training — defaults match config.py (CARE-GNN on YelpChi)
python train.py --data yelp  --model CARE
python train.py --data amazon --model CARE --batch-size 256     # Amazon uses smaller batch

# CAPN policy network (replaces the heuristic bandit)
python train.py --data yelp --model CARE --use-capn \
                --use-actor-critic --gnn-warmup-epochs 5 --lambda-policy-ramp-epochs 5 \
                --llm-priors-file data/llm_priors/yelp_priors.json

# Full three-pillar framework on YelpChi (main thesis configuration)
python train.py --data yelp --model CARE --use-capn --use-actor-critic \
                --gnn-warmup-epochs 5 --lambda-policy-ramp-epochs 5 \
                --llm-priors-file data/llm_priors/yelp_priors.json \
                --text-enrichment gate --text-state-enrichment

# Ablation sweeps (see doc/commands.md for full study names)
python ablation.py --study all_capn --data both
python ablation.py --study capn_llm_state --data amazon

# LLM preprocessing (run once per dataset before --enrichment-mode is used)
python -m llm.compute_node_statistics        --data amazon   # writes node_statistics.npz

# Thesis-stats verification (reproduces every dataset number in Chapter 3.1)
python scripts/verify_chapter3_final.py

# Regenerate the professor-facing PowerPoint from scratch
```

## Architecture — three pillars plus orchestration

The unified framework is intentionally additive: each pillar can be toggled by a single flag and
its code is confined to one module. When tracing a training run, the wiring lives in `train.py`
around lines 260–500 (feature-gate wiring, policy/critic construction, optimiser split).

### GNN pillar (backbone)
- `model.py :: OneLayerCARE` / `CAPNOneLayerCARE` / `MultiLayerCARE` — the multi-relation GNN.
  `CAPNOneLayerCARE.loss()` is where supervised loss, policy-gradient, and critic MSE are summed
  (`eq:unified-loss` in the thesis).
- `layers.py` — intra/inter-relation aggregators (`IntraAgg`, `InterAgg`) plus the legacy
  `RLModule` (heuristic bandit). The bandit is the *inherited* threshold updater that CAPN
  replaces; it still runs when `--use-capn` is off.
- `graphsage.py` — GraphSAGE reference baseline only; not part of the unified framework.

### RL pillar (CAPN)
- `capn.py` — everything CAPN-specific: `EnhancedLabelPredictor`, `StateConstructor`,
  `PolicyNetwork` (Beta-parameterised, emits per-node thresholds), `ValueNetwork` (critic),
  `MultiViewDistance`, `ShapedRewardComputer`, `TextFeatureGate`, `GatedEmbedding`.
- Hyperparameters live in `config.py`; CLI flags override them in `train.py`.
- The production configuration is **actor-critic** (`--use-actor-critic`) with warmup/ramp
  5/5 — the code-level defaults (`0/0`) disable warmup, so forgetting these flags leads to
  unstable Yelp runs.

### LLM pillar
- `llm/compute_node_statistics.py` produces the 26-dim structural profile per node (Part 1).
- `llm/generate_risk_scores.py` — Claude Haiku 4.5 (`claude-haiku-4-5-20251001`,
  `temperature=0`) turns that profile into 6 fraud-relevant scores. Template fallback is
  deterministic.
- `llm/generate_text_risk_scores.py` — YelpChi-only Part 2: 6 text-risk scores from raw review
  text, cached at `llm_embeddings/yelp/text_risk_scores.pt`.
- `llm/projector.py` — the score projector used in the CAPN state; mode auto-selects based on
  input dim (linear ≤8, small MLP 9–32, deep MLP ≥128).
- `llm_priors.py` — bias-initialisation priors for the policy network, consumed via
  `--llm-priors-file`.
- All LLM outputs are **precomputed once and loaded at train time** — no API calls inside the
  training loop.

### Orchestration
- `config.py :: CareConfig` is the single source of truth for defaults; `train.py` builds the
  same dataclass from CLI flags. Any new hyperparameter should be added here first.
- `ablation.py` is the sweep dispatcher. Study names (`capn`, `capn_label`, `capn_reward`,
  `capn_llm_state`, `all_capn`, …) are defined at the bottom of the file and map to builders
  like `get_capn_feature_enrichment_experiments()`.

## What NOT to change casually

- The data-split function in `train.py` uses `random_state=2` and the CARE-GNN convention that
  Amazon nodes 0–3,304 are excluded from labelled splits. Reordering the splits would silently
  invalidate every Chapter 4 number.
- `config.py :: test_size = 0.60` + `val_size = 0.15` + `use_validation = True` yields the
  25/15/60 split documented in §3.2.7. Toggling `use_validation` off drops the split to 40/60
  and disables early-stopping checkpoint selection — almost never what you want.
- `TextFeatureGate` initialises its gate at `-2` (sigmoid ≈ 0.12) on purpose — this is why
  early-training behaviour matches CARE-GNN closely.
